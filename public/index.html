Features

为生产环境而生

不只是提取颜色，更是一套克制、可靠、可观测的 API。

主色 + 调色板

一次请求返回主色调与按占比排序的调色板，ratio 精确到小数点后 4 位。

广泛格式支持

自动解码 JPEG、PNG、GIF、BMP、WebP、AVIF，无需前端预处理。

多种颜色格式

hex、rgb、hsl、cmyk 任选，服务端统一换算，前端直接渲染。

两种提取算法

Median Cut（默认，快）与 K-Means（更精细），按场景自由切换。

智能过滤

自动跳过纯黑 / 纯白结果，返回更有代表性的主题色。

生产级防护

Referer 白名单、单 IP 限流、并发上限、下载体积与像素限制、超时控制。

可插拔缓存

默认内存缓存，可一键切换 Redis 或 MongoDB，降低重复计算开销。

开箱可观测

内置 /health 健康检查与 /metrics Prometheus 指标，接入监控零成本。

零配置部署

全部逻辑收敛在单个 Go 文件，天然适配 Serverless 冷启动，一份 vercel.json 即可上线。

How it works

一次请求的三个阶段

从 URL 到调色板，服务端一气呵成。

01 · Develop

提交请求

传入图片 URL 与参数：颜色格式、颜色数量、提取算法、是否跳过背景边缘。

02 · Preview

提取分析

服务端下载并降采样图片，用 Median Cut 或 K-Means 对像素聚类，智能过滤极端色。

03 · Ship

返回调色板

主色 + 按占比排序的调色板以 JSON 直出，并写入可插拔缓存供下次秒回。

API Reference

三个端点，一个契约

所有响应均为统一 JSON 结构：{ code, message, data }。

GET /api

从图片 URL 提取主色与调色板。

?img=https://example.com/a.jpg   # 必填，需 URL 编码
&format=hex|rgb|hsl|cmyk          # 默认 hex
&colors=1-10                       # 默认 1
&algorithm=mediancut|kmeans        # 默认 mediancut
&maxWidth=32-4096                  # 默认 400
&skipBackground=true|false         # 默认 false
GET /health

健康检查与运行统计（请求数、缓存命中率、错误数）。

GET /health → { "status":"up", "requests":N,
  "cacheHitRate":0.42, "recentErrors":0 }
GET /metrics

Prometheus 文本格式指标，直接对接监控。

GET /metrics
# TYPE img2color_requests_total counter
img2color_requests_total 128
